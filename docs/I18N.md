# Internationalisation (i18n)

The frontend supports English (`en`, default) and Arabic (`ar`, right-to-left) using
`i18next` + `react-i18next`. All pages are translated (see "Coverage" below); a few server-provided strings are not.

## Coverage

Translated (en + ar, RTL-aware):

- App shell: `App.tsx` loading fallback, `ErrorBoundary`, `PrivateRoute`, `Sidebar`, `NotificationBell`, `LanguageSwitcher`.
- Pages: Login, Signup, Dashboard overview, Patients (list, admit modal, detail, edit, report upload), Beds & Wards (page and
  `BedModal`), Staff & Shifts (directory, `StaffModal`, `StaffCard`, `ShiftTimeline`), Appointments (page and
  `NewAppointmentModal`), Vitals Monitor (page, `VitalsCard`, `VitalsChart`, `AlertsPanel`), Incidents (page and `IncidentModal`),
  Dispatch, Settings.
- Shared: `components/Form/*` (labels, placeholders, helper text, option labels, validation messages, default buttons),
  `ConfirmModal`, `ConfirmDeleteDialog`, `hooks/useCrud` toasts, `services/api` interceptor errors, `constants/hospital`.
- Dates, times and counts use the active locale (`i18n.language`) where they are rendered in pages and components.

Not translated (by design or still pending):

- Free text coming from the API or database: patient/staff names, diagnoses, ward names, notification titles/messages,
  socket alert messages (the dispatch critical-alert toast), audit data, and backend error messages that the API returns.
- Zod messages in `configs/entityConfigs.ts` (`*ValidationSchema`); the schemas are not used by the UI, `FormModal` validates
  and translates its own messages.
- Values that are sent to the API stay English (enums, `Day` shift on signup, `hospitalId`); only their labels are translated.
- `e2e-real` and the mocked Playwright suite run in English.

## Files

- `frontend/src/i18n/index.ts` - init, language detection, `dir`/`lang` handling, persistence.
- `frontend/src/i18n/locales/en.json`, `ar.json` - translation resources (keep both files in the same shape).
- `frontend/src/components/LanguageSwitcher.tsx` - toggle button (Sidebar and Login page).

## How it behaves

- Initial language: saved choice in `localStorage` (`hospilink_lang`) -> browser language (`ar*` or `en*`) -> `en`.
- On every change `document.documentElement.lang` and `dir` (`rtl` for `ar`) are updated and the choice is saved.
  All `localStorage` access is wrapped in `try/catch`; if storage is blocked the app still works, the choice just is not remembered.
- Missing keys fall back to English.

## Adding or translating strings

1. Add the key to **both** `en.json` and `ar.json`. Group keys by area (`auth`, `sidebar`, `dashboard`, ...); create a new group per page.
2. Use it in the component:

   ```tsx
   import { useTranslation } from 'react-i18next';

   const { t } = useTranslation();
   <h1>{t('patients.title')}</h1>
   <p>{t('dashboard.bedsInUse', { occupied, total })}</p> // "{{occupied}} of {{total}} beds in use"
   ```

   Configs that cannot call `t` at module level (for example `configs/entityConfigs.ts`) store the **key** in `label`,
   `placeholder`, `helperText` and option `label`; `FieldRenderer`/`FormModal` translate them with
   `t(text, { defaultValue: text })`, so a plain English literal still renders as-is.
3. Translate `aria-label`, `placeholder` and `title` attributes too, not only visible text.
4. Do not translate data values coming from the API (names, enum values sent back to the server). To show an enum
   label, map it to a key and pass `defaultValue` so unknown values still render, e.g.
   `t(\`dashboard.appointmentTypes.${type}\`, { defaultValue: type })`.
5. Keep internal identifiers (for example the dashboard tab ids stored in the cookie) in English and translate only the label.
6. Dates and times: pass `i18n.language` as the locale to `toLocaleDateString` / `toLocaleTimeString`.

## Adding a language

Create `locales/<code>.json`, register it in `resources` and `SUPPORTED_LANGUAGES` in `i18n/index.ts`, add it to
`RTL_LANGUAGES` if it is right-to-left, and update the native names in `LanguageSwitcher.tsx`.

## RTL layout

Use Tailwind logical utilities instead of left/right ones so the layout mirrors automatically:
`ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`, `text-start`/`text-end`, `border-s`/`border-e`, `rounded-s`/`rounded-e`.
For directional icons (chevrons, arrows) add `rtl:rotate-180`. Use `rtl:` / `ltr:` variants for one-off cases.

## Tests

- `src/i18n/__tests__/locales.test.ts` fails when `en.json` and `ar.json` differ in keys, contain empty values, or use
  different `{{placeholders}}`/tags. Run it after every locale edit.
- `src/pages/__tests__/pagesArabic.test.tsx` and `src/components/__tests__/componentsArabic.test.tsx` render pages and shared
  components in Arabic (`await i18n.changeLanguage('ar')`) and assert translated text and `dir="rtl"`.

Vitest setup (`src/test/setup.ts`) resets the language to `en` before every test, so existing assertions stay in English.
Language switching is covered in `src/components/__tests__/LanguageSwitcher.test.tsx`.
